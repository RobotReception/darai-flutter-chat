# هوية الحساب وتبديل المستخدم

الزائر لا يحتاج خادم هوية خاصًا. للمستخدم المسجل، تحتاج نقطة API في خادم تطبيقك تتأكد من جلسة المستخدم وتصدر identity_token قصير الصلاحية وفق إعداد قناة داري. إعداد سر القناة يتم بين فريق داري ومطور الخادم عبر قناة آمنة؛ لا توجد أوامر إدارة خادم مطلوبة من مستخدم التطبيق.

مرّر `Future<String> Function()` في `getIdentityToken`. تستدعيها الحزمة في كل إعادة اتصال بمهلة 15 ثانية. استخرج الرمز من جلسة المستخدم الفعلية ولا تقبل معرف مستخدم يرسله العميل دون تحقق.

بوابة داري الحالية تستخدم HS256 وهوية الحساب في `sub` وصلاحية `exp` لا تتجاوز 15 دقيقة. طابق العقد الفعلي مع فريق داري قبل التنفيذ؛ الحزمة لا تنشئ التوقيع. لا ترسل `external_id` منفردًا لإثبات الهوية.

في الوضع المسجل تُحذف هوية الزائر السابقة من التخزين المحلي. إذا رفضت البوابة التوقيع وأعادت visitorKey تتوقف الحزمة بدل مشاركة محادثة زائر مع مستخدم مسجل. فشل callback يوقف محاولة الاتصال ويعاد لاحقًا؛ لا تحول callback الفاشل إلى قيمة فارغة.

عند تسجيل الخروج أو تبديل الحساب:

1. أغلق شاشة الدردشة الحالية؛ `dispose` يغلق العميل ويمسح ذاكرته.
2. امسح بيانات المحادثة وأي حالة احتفظ بها تطبيقك خارج الحزمة.
3. افتح شاشة جديدة: callback للمستخدم الجديد أو بدون callback للزائر.
4. لا تعِد استخدام عميل الحساب السابق.

اختبر حساب أ ثم ب ثم زائر على الجهاز نفسه. لا تفترض أن تغيير callback داخل الشاشة الحالية يغيّر جلسة العميل القائمة. استخدم شاشة جديدة أو Key مختلفًا.
