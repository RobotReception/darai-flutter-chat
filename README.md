# داري — حزمة دردشة Flutter

حزمة قابلة للتعديل لإضافة دردشة داري إلى تطبيق Android أو iOS. تتضمن عميل اتصال مستقلًا، شاشة عربية، إرسال النصوص والصور، ومثال Android. تستطيع استخدام الشاشة مباشرة أو بناء واجهتك فوق العميل.

**الإصدار: `0.1.0` — حزمة تكامل أولية.** لا تتصل بأي قناة افتراضيًا. أدخل بيانات قناتك من لوحة داري. حالة التحقق الفعلية وحدود الاختبارات في [VALIDATION.md](VALIDATION.md).

## البداية السريعة

1. ثبّت Flutter `3.41.0` لتطابق بيئة التحقق (Dart `3.11.0`). قيود الحزمة Flutter `>=3.38.0` وDart `^3.10.8`، ويجب استيفاء القيدين معًا.
2. افتح لوحة داري ← القنوات ← قناة التطبيق ← دليل الربط، وانسخ **Base URL وChannel ID وApp ID**.
3. داخل `example` انسخ `darai-config.example.json` إلى `darai-config.json` واستبدل القيم ببيانات قناتك.
4. شغّل جهاز Android أو محاكيًا، ثم:

```sh
cd example
flutter pub get
flutter run --dart-define-from-file=darai-config.json
```

الأوامر نفسها تعمل على PowerShell. ملف الإعداد الخاص بك مستبعد من Git. بدون إعداد صحيح يعرض المثال إرشادًا واضحًا ويعطل زر الدردشة. تغيير الإعداد يتطلب إعادة تشغيل كاملة؛ Hot Reload لا يغيّر قيم `String.fromEnvironment`.

تفتح الدردشة من زر «فتح الدردشة». هذا المثال يوضح كيف تعرضها في أي وقت من شاشة أو قائمة في تطبيقك.

## ماذا تتضمن الحزمة؟

| الجزء | الغرض |

## الدمج في تطبيق موجود

انسخ الحزمة إلى مجلد `packages/darai_chat` في مشروعك، ثم أضف:

```yaml
dependencies:
  darai_chat:
    path: packages/darai_chat
```

شغّل `flutter pub get`. أنشئ ملف إعدادات واحدًا في تطبيقك:

```dart
import 'package:darai_chat/darai_chat.dart';

const chatConfig = DaraiChatConfig(
  baseUrl: 'https://YOUR-DARAI-HOST',
  cId: 'YOUR_CHANNEL_ID',
  appId: 'YOUR_APP_ID',
);
```

افتح الشاشة من زر:

```dart
Navigator.of(context).push(
  MaterialPageRoute<void>(
    builder: (_) => const DaraiChatScreen(config: chatConfig),
  ),
);
```

`baseUrl` هو أصل HTTPS فقط، بدون `/ws` أو مسار أو Query. معرّفات القناة والتطبيق بيانات ربط عامة وليست أسرار توقيع. لا يلزم Origin لتطبيق Android أو iOS الأصلي. هذه الحزمة تستخدم `dart:io`؛ Flutter Web غير مدعوم.

## تخصيص الشاشة

```dart
DaraiChatScreen(
  config: chatConfig,
  title: 'خدمة العملاء',
  welcomeTitle: 'كيف نساعدك؟',
  welcomeMessage: 'اكتب استفسارك هنا.',
  allowImageAttachments: true,
  textDirection: TextDirection.rtl,
  theme: DaraiChatTheme.light(
    primary: const Color(0xFF1B5091),
    fontFamily: 'DaraiFont',
  ),
)
```

اللون الأساسي الافتراضي هو لون داري `#1B5091`. الحزمة لا تتضمن ملفات خطوط تجارية؛ تستخدم خط النظام حتى تضيف خطًا مرخصًا في تطبيقك. شرح الخط والألوان والواجهة في [التخصيص](docs/CUSTOMIZATION.md). المظهر المرفق فاتح؛ دعم مظهر داكن كامل يحتاج تعديل ألوان الحالات والفقاعات أيضًا.

## Android وiOS

المثال يتضمن Android runner وصلاحية الإنترنت. في تطبيقك أضف داخل `<manifest>` وخارج `<application>`:

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

اترك HTTPS/WSS ولا تسمح باتصالات HTTP عامة. متطلبات Gradle وJava وAndroid SDK يحددها Flutter ونسخ الإضافات، ويمكن تشخيصها بـ `flutter doctor -v`.

لمشروع iOS موجود، أضف إلى `ios/Runner/Info.plist`:

```xml
<key>NSPhotoLibraryUsageDescription</key>
<string>اختيار صورة لإرسالها في محادثة الدعم.</string>
```

الواجهة الحالية تستخدم معرض الصور فقط، وليس الكاميرا. راجع إعداد Keychain الخاص بـ `flutter_secure_storage` لمشروع iOS. المثال لا يتضمن iOS runner؛ لإنشائه على جهاز التطوير:

```sh
cd example
flutter create --platforms=ios --project-name darai_chat_example .
```

راجع التغييرات وأضف وصف الصور قبل التشغيل. بناء iOS واختباره يحتاج macOS وXcode وإعداد التوقيع. مثال Android يستخدم توقيع debug حتى في إعداد release للتجربة؛ استبدله بمفتاح إصدار تطبيقك قبل توزيع التطبيق.

## استخدام العميل بدون الشاشة

```dart
final client = DaraiChatClient(
  config: chatConfig,
  onEvent: (event) {
    // حدّث واجهتك حسب الحدث؛ لا تسجّل محتوى المحادثات أو الرموز.
  },
);
await client.connect();
final messageId = client.sendText('مرحبًا');
// عند طلب المستخدم إعادة المحاولة: client.retry(messageId);
// عند عرض رسالة واردة: client.markRead(serverMessageId);
// عند إغلاق الصفحة: await client.dispose();
```

احتفظ بمعرّف الرسالة عند إعادة المحاولة. `message.ack` يعني **قبول الرسالة** في الخدمة، وليس قراءتها أو وصول رد. العميل يحتفظ بالرسائل المعلقة في الذاكرة ويعيد إرسالها بعد عودة الاتصال بنفس المعرّف. لا يوجد حفظ دائم للرسائل.

## هوية الزائر وهوية المستخدم

الوضع الافتراضي زائر: يحفظ العميل مفتاحًا موقّعًا في التخزين الآمن لكل مضيف وقناة، ثم يستخدمه عند الاتصال التالي. هذا يثبت استمرار جلسة الزائر، ولا يسترجع سجل الرسائل المعروضة.

لربط مستخدم مسجل، مرّر `getIdentityToken` إلى الشاشة أو العميل. يستدعي العميل هذه الدالة عند كل اتصال، ويجب أن تجلب رمزًا جديدًا من **خادم تطبيقك** بعد التحقق من جلسة المستخدم. لا توقّع الرموز داخل Flutter، ولا تضع سر القناة فيه.

```dart
DaraiChatScreen(
  config: chatConfig,
  getIdentityToken: () => accountApi.fetchDaraiIdentityToken(),
)
```

`accountApi` مثال لخدمة تنفذها في تطبيقك. الحزمة لا توفر API تسجيل دخول. إذا تعذر الرمز أو أعاد خادم داري جلسة زائر بدل هوية الحساب، يفشل الاتصال ولا ينتقل تلقائيًا إلى زائر. راجع [الهوية وتبديل الحساب](docs/IDENTITY.md).

## الصور والمرفقات

الشاشة تختار صورة JPEG أو PNG أو WebP وتُظهر حالة انتظار الإقرار. طبقة العميل توفر `uploadFile` و`sendUpload` للأنواع `image` و`audio` و`video` و`document`، لكن واجهة الاختيار الحالية للصور فقط؛ قبول الأنواع والحجم النهائي تحدده إعدادات خادم داري.

يرفع العميل الملف بـ Bearer token مؤقت ثم يرسل `upload_token` عبر WebSocket. لا يُخزّن Bearer token في التخزين الدائم. إذا انتهت صلاحية رمز رفع صورة معلقة، يجب إعادة رفع الملف؛ الحزمة لا تجدد رموز الرفع تلقائيًا. المرفقات الواردة تظهر حاليًا كنص بديل، وليس عارض صور أو ملفات. تفاصيل الأحداث والرفع في [البروتوكول](docs/PROTOCOL.md).

## الأخطاء والتشخيص

| الحالة | الإجراء |
|---|---|
| المثال يطلب بيانات القناة | راجع JSON وشغّل مع `--dart-define-from-file` |
| `app_id mismatch` | طابق App ID مع القناة نفسها |
| مهلة أو إعادة اتصال | راجع الإنترنت وHTTPS وWSS ومسارات البوابة |
| HTTP 401/403 | راجع القناة وصلاحية الرمز وإعداد الهوية |
| `Identity was rejected` | راجع توقيع خادمك والصلاحية؛ لا تستخدم external_id منفردًا |
| HTTP 400 عند الرفع | حقل `type` قيمته `image` وليس `image/png` |
| HTTP 415 | راجع نوع الملف الفعلي وMIME وصيغ الخادم المدعومة |
| رسالة بلا إقرار | انتظر أو أعد المحاولة بنفس المعرف، ولا تعرضها كمقروءة |

الواجهة تعرض رسائل بسيطة، بينما أحداث `connection.error` تحتوي مرحلة الفشل للمطور. لا تضف تسجيلًا لرموز الاتصال أو مفاتيح الزائر أو نصوص الرسائل. تفاصيل ردود HTTP غير معروضة لتجنب كشف بيانات داخلية.

## حدود الإصدار

- لا يوجد API لاسترجاع سجل المحادثة في الحزمة.
- الرسائل المعروضة والمعلقة في الذاكرة؛ إغلاق الشاشة أو قتل التطبيق يفقدها.
- لا توجد إشعارات FCM/APNs أو خدمة اتصال في الخلفية.
- فتح أكثر من شاشة ينشئ أكثر من عميل؛ افتح جلسة واحدة لكل شاشة دردشة.
- تغيير config أو هوية المستخدم أثناء بقاء الشاشة مفتوحة يحتاج إغلاقها وإنشاء شاشة جديدة.
- لا يوجد عارض للمرفقات الواردة ولا تجديد تلقائي لرمز رفع منتهي.
- إقرار القراءة يصدر في المسار الحالي عندما يكون التطبيق في المقدمة. عند العودة للمقدمة يُجدّد الاتصال؛ هذا ليس خدمة اتصال في الخلفية.
- لا تدعم Flutter Web أو تجربة داكنة كاملة في هذا الإصدار.

## الخصوصية والإطلاق

الحزمة ترسل الرسائل التي يكتبها المستخدم والملفات التي يختارها ومعرّفات جلسة الربط. لا تقرأ قاعدة بيانات تطبيقك ولا ترسل أرصدة أو سجلات تلقائيًا. إذا احتوت الرسالة أو الصورة على بيانات شخصية فستصل إلى خدمة داري. أضف الإفصاح المناسب في تطبيقك، وحدد سياسة الاحتفاظ مع الخدمة.

قبل الإطلاق: استخدم بيانات قناة البيئة الصحيحة، اختبر حدود المرفقات، اختبر عزل الحسابات إن فعّلت الهوية، وحدد متطلبات السجل والإشعارات. لا تعتبر تنزيل المثال تفعيلًا لهذه الميزات.
